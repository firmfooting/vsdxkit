# Phase 7: cleanup, so the 1.0 surface is only the user API

Epic #29, issues #115, #116 and #117. Authority:
- `.hermes/plans/2026-09-12_simplification-usability-refactor.md`, "Phase 7 — cleanup";
- the Phase 6 spec's "Out of scope" section (`.hermes/plans/2026-09-24_phase6-spec.md`);
- the maintainer's decisions of 2026-09-26, recorded below.

## Goal

After this phase:

- every public name in the wheel is user API: listed in `docs/classes.rst` or its topic page, or kept on purpose and named in the migration guide as unchanged;
- no dead member, dead branch or 0.x holdover remains in `src/`;
- the installed wheel's public type completeness is gated in CI at 95% or more. #117 and #29 both ask for this;
- the coverage ratchet sits at the measured total;
- the README and the primary docs show only the 1.0 API, in 1.0 style.

The plan's rule still holds: "Do not split a class to meet a line-count target."

## Where things stand (refactor/phase6c-seams at 782f801)

## Decisions

### The maintainer's decisions (2026-09-26)

1. **Every package internal on `Document` and `Page` becomes private.** That covers the raw part XML, the part-level attributes and the ID helpers. Anyone who needs a part uses the part names in `vsdxkit.partnames`, or asks for an API.
2. **`VisioFileDiff` becomes internal.** It leaves the public surface.
3. **Both holdovers go.** `Document.filename` becomes read-only; `save(target)` is how to save elsewhere. The `Shape.geometry` setter is deleted.
4. **Examples name the document `document`,** not `vis`, in the README and the docs. `page.vis` keeps its name, as Phase 6 ruled. Tests keep `vis`.

### Dead code is deleted (#116)

- Every item under "Dead statics" and "Dead members" above is deleted, with no replacement.
  - Callers of `Document.pretty_print_element` use `xmlio.pretty_print_element`.
  - The tests of `Document.apply_text_context` move to `Page.apply_text_context`, which already resolves master inheritance.
  - `Cell.__repr__` uses `formula`.
  - The `Document._part_tree` forward is inlined into its callers as `xmlio.require_tree`.
- There is one "read an XML part or raise `MissingPartError`": `PackageStore.require_xml`. `Document._require_part_xml` and `MasterCatalog._required_root` call it or are replaced by it.
- A public member with no internal caller stays when it is documented user API, such as the `require_*` finders, the swimlane methods and `retarget`. The test is "documented or kept on purpose", not "called from `src/`".
- Every deleted name that `tools/api-0.8.0.txt` lists gets a migration-guide entry. `tools/check_migration_guide.py` enforces this.

### One owner allocates shape IDs: the page

- The allocator moves from `Document` to `Page` as private methods. Their behaviour and docstrings move unchanged:
  - `Page._renumber_shape_ids(subtree: Element, id_map: dict[str, int] | None = None) -> dict[str, int]`: the one primitive, which sweeps the formulas and the `Connect` records over the whole page (#328).
  - `Page._copy_shape_xml(element: Element) -> Element`: a copy, renumbered and appended to the page's `Shapes`.
  - `Page._increment_shape_ids(...)` and `Page._set_new_id(...)`: the private steps.
- Today `Page._copy_shape_xml` and `Page._renumber_shape_ids` forward to the document. They become the implementations.
- `Document` loses `copy_shape`, `renumber_shape_ids`, `increment_shape_ids`, `increment_sub_shape_ids`, `set_new_id`, `update_ids` and `insert_shape` (and with it the `page_path` holdover). `pages._DocumentSeam` loses the members it declared for them.
- **Sheet references are rewritten by one pure function.** `shape_tree.remap_sheet_references(subtree: Element, id_map: Mapping[str, int]) -> None` rewrites every `Sheet.N!` and `SheetN!` in the cell formulas under `subtree`, keeping each reference's own form.
  - `shape_tree.SHEET_REFERENCE` is the one regex. `pages` uses it wherever it uses `_SHEET_REFERENCE` today.
  - `shape_tree` already holds the element-level walks and knows nothing of the wrappers, so this belongs there.
  - `shapes.parent_of` and `shapes.find_or_create_shapes_tag` move there as well, because they are element-level tree functions.
  - `tests/helpers/package_validator.py` keeps its own independent copy of the regex on purpose, as an oracle.
- **`RenderTarget` declares only `pages`.** `templating` renumbers a loop's copies with `page._renumber_shape_ids(shape.xml)`. It already imports the concrete `Page`.

### Package internals are private (decision 1)

- **`Document`:**
  - the raw part XML becomes `_pages_xml`, `_pages_xml_rels`, `_content_types_xml`, `_app_xml`, `_document_xml`, `_document_xml_rels` and `_masters_xml`, keeping their write-through behaviour;
  - `load_pages` becomes `_load_pages`;
  - `get_master_page_by_id` becomes `_master_page_by_id`;
  - `PAGES`/`MASTERS` become `_PAGES`/`_MASTERS`.
- **`Page`:** `filename`, `page_id`, `rel_id`, `master_unique_id`, `rels_xml` and `rels_xml_filename` gain a leading underscore.
  - `master_base_id` is already deleted as dead.
  - `MasterCatalog` sets `page._master_unique_id` as it does now.
- **Seams:** `_PageSeam`, `_ConnectorPage` and `_DocumentSeam` rename their members to match.
- **Documentation:**
  - `PageView`'s docstring and the guide stop listing "part-level attributes you reach through the `Page` you hold", because there are none left.
  - The guide gets one entry per removed name: "internal in 1.0; no public replacement", or the user API that replaces it.
- **What stays:** within the package, a single leading underscore means package-internal, so one module may use another's underscored member. Phase 7 does not add seams for those.

### The holdovers go (decision 3)

- **`Document.filename`** becomes a read-only property. It returns the path the document was opened from, or `None`.
  - `save()` with no target writes back to that source. Assigning to `filename` raises `AttributeError`.
  - The guide entry says to use `save(target)`.
- **`Shape.geometry`'s setter** is deleted. Reading `shape.geometry` is unchanged.

### `VisioFileDiff` leaves the public surface (decision 2)

- `src/vsdxkit/vsdxdiff.py` is deleted.
- Its code moves to `tests/helpers/package_diff.py` as `PackageDiff`. It keeps its behaviour, including its size limits, which raise a helper-local error. Following the `tests/helpers` rule, it imports nothing from `vsdxkit`.
- Its tests move with it and keep their assertions.
- The guide entry says `VisioFileDiff` is gone and is not replaced.
- #376 is closed as moot, since no public API reads packages outside `PackageLimits` any more.

### The type-completeness gate (#117)

- **Annotations:** everything verifytypes reports gets one:
  - the six `__repr__`/`__str__` methods;
  - every module `logger`;
  - `formulae.func_map`;
  - the `Geometry`, `GeometryRow` and `GeometryCell` attributes;
  - `PackageStore.source`;
  - `PackageLimitError.reason`.
- **`tools/check_type_completeness.py <wheel> --fail-under <score>`** builds a throwaway venv outside the repository. It installs the wheel and a pinned `pyright`, then runs `pyright --verifytypes vsdxkit --ignoreexternal --outputjson` from that directory, because pyright run from the repository root adds `src/` to its path. It prints the score and the unknown symbols, and exits non-zero below the threshold.
- **The threshold** is the score measured once this phase lands, rounded down to one decimal place. It is never below 95.0, and it is a ratchet that only goes up, like coverage.
- **CI:** the `build distribution` job runs the check against the wheel it built, and uploads the JSON report as an artifact.
- **Docs:** the score is stated in `CONTRIBUTING.md` beside the other gates.

### Other gates

- **Wheel contents:** `tools/smoke_wheel.py` asserts that the wheel's `vsdxkit/*.py` set equals `src/vsdxkit/*.py`.
- **Tracked files:** `tests/test_tracked_files.py` adds `.venv/*`, `build/*` and `dist/*` to its generated-artefact patterns.
- **Coverage:** `[tool.coverage.report] fail_under` rises to the total measured after 7b, rounded down to a whole number, and its comment gets the new date.

### Primary docs (decision 4)

- **Examples:** the README and every `docs/*.rst` example name the document `document`.
- **Stale docstrings:** the five listed under "Where things stand" are rewritten against the 1.0 API.
- **`docs/classes.rst`:** it documents `is_macro_enabled`, `master_pages`, `master_index` and `load_master_pages`. The guide already calls them unchanged, so they are user API. It stops listing anything that 7b makes private.
- **The guide:** the duplicate `shape.data_properties` entry is removed.

## Out of scope

- **#319**, folding `get_or_create_cell` into `_write_cell`. It is a separate open issue.
- **Folding `Cell` and `GeometryCell` together.** It would change public API beyond `func`.
- **Moving `Cell` or `DataProperty`.** Doing so removes no cycle, so the plan's condition is not met.
- **Moving the text-run helpers.** Once `Document.apply_text_context` is gone, only `shapes` uses them.
- **Underscored access across modules within the package.** See "What stays".
- **`Document.__init__(package, filename)`.** Users call `Document.open`.
- **Version and classifier changes.** They belong to Phase 8 and release-please.
- **Test cosmetics:** file names such as `test_visiofile*.py` and `test_reanchor.py`, and `vis` in tests.
- **The behaviour behind the live TODOs** (`document.py:405`, `:941`; `geometry.py:127`, `:146`, `:271`). They mark real paths, not dead ones.
