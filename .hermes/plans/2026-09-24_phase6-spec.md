# Phase 6: templating as a function, and every import arrow pointing down

Epic #28, issues #113 and #114. Authority:
`.hermes/plans/2026-09-12_simplification-usability-refactor.md`, "Ownership
and dependency rules" as amended on 2026-09-23, and "Phase 6".

## Goal

After this phase, the plan's acceptance holds:

- `Document` has no mixin bases;
- dependency arrows point down, with `Protocol`s at the seams;
- the runtime annotation-resolution ratchet is at zero;
- the Jinja fixtures and the recorded Visio observations pass.

It adds the import-graph test #114 asks for, so the direction stays fixed.

## Where things stand (main at 58536ab)

A static scan of every `import` statement in `src/vsdxkit` shows the
following.

- **Runtime.** The module-level runtime graph has no cycle.
- **The mixin.** `Document(JinjaTemplatingMixin)` is the only mixin base
  left. The mixin contributes `render` and five public statics:
  `jinja_render_shape`, `jinja_set_selfs`, `unescape_jinja_statements`,
  `jinja_create_for_loop_if` and `jinja_page_showif`.
- **A hidden cycle.** `media` opens its bundled donors as `Document`s. That
  gives a cycle `media → document → pages → media`, and
  `connectors → media → … → shapes → connectors`. `pages.py` and
  `connectors.py` hide it with a function-local `from vsdxkit import media`.
  That also reaches a sibling through the package root.
- **Siblings through the root.** `masters.py` and `pages.py` do
  `from vsdxkit import relationships`. `shapes.py` does `import vsdxkit` for
  one `vsdxkit.namespace`, which it also imports by name.
- **Upward edges.** Five `TYPE_CHECKING` imports point up. The amended plan
  says these are not a seam.

  | Lower module | Imports for typing | What it uses |
  |---|---|---|
  | `swimlanes` | `pages.Page` | `_attached`, `children`, `name` |
  | `connectors` | `pages.Page` | `name`, `shapes`, `vis`, `_connects`, `_add_connect`, `_remove_connect_records` |
  | `connectors` | `shapes.Shape`, `shapes.Connector` | `ID`, `center_x_y`, `master_shape`, `xml`, `page`, `begin_x`/`begin_y`/`end_x`/`end_y`, `set_start_and_finish`, `get_or_create_cell`, `_cell`, `_require_attached` |
  | `shapes` | `pages.Page` | `name`, `xml`, `shapes`, `is_master_page`, `vis`, `_attached`, `_delete`, `_connects`, `_ensure_page_master_rel`, `_carry_relationships`; through `vis`: `get_master_page_by_id`, `copy_shape`, `renumber_shape_ids`, `_master_is_one_d`, `_masters_for`, `_master_revision` |
  | `pages` | `document.Document` | `pages`, `pages_xml`, `masters_xml`, `_package`, `_set_part_xml`, `_rename_page_in_app_xml` |

- **The ratchet.** `UNRESOLVED` still lists four signatures: `Page.__init__`,
  `Shape.__init__`, `Shape.copy` and `Shape.master_page`.

The namespace constants stay in the package root. The amended plan keeps them
there. The root imports nothing, so `from vsdxkit import namespace` cannot
form a cycle. #114's older idea of a separate `namespaces.py` is superseded.

## Decisions

### Templating is a function (#113)

- `vsdxkit.templating.render_document(document, context)` renders a document
  in place.
  - Its annotation is `render_document(document: RenderTarget, context: Mapping[str, object]) -> None`.
  - `RenderTarget` is a `Protocol` in `templating.py` holding what rendering
    uses: `pages`, and `increment_sub_shape_ids(shape, page)`.
  - `templating.py` is below `document.py`, so it cannot name `Document`.
- `Document.render(context)` stays the public entry point and calls
  `render_document(self, context)`. `Document` has no bases other than
  `object`.
- `JinjaTemplatingMixin` is deleted. Its five statics become private module
  functions: `_render_statements`, `_apply_set_self`,
  `_unescape_statements`, `_open_block` and `_page_is_shown`. The regexes
  and `_SETTABLE` become private module constants.
  - The loop, `showif` and `set self` conventions are unchanged. The
    `test_jinja*.py` fixtures and `test_templating_sandbox.py` are the
    contract.
- `context` is a `Mapping` rather than a `dict`, which widens what callers may
  pass.
- The migration guide names the removed statics and the mixin. The guide check
  lists them once they are gone from `Document`.

### Donors without the cycle

- `media.py` keeps the bundled-donor knowledge: the paths, the kind table,
  the sentinels, the per-process cache and its lock. It stops importing
  `Document`.
- Its loaders take the opener as an argument, for example
  `_kind_shape(kind, open_document)`. They declare a private `Protocol` for
  the donor document they need (`pages`, `_get_style_by_id`). `media` then
  imports only `errors`, `shape_kind`, `pages` and `shapes`, and nothing
  above `pages`.
- `Document` gains two private methods, which pass `Document.open` down:
  - `_kind_source(kind) -> Shape`: the donor shape for a kind;
  - `_copy_connector(page) -> Connector`: a copied donor connector on
    `page`, its sentinel text cleared and its line style imported unless
    the document already has a style with that ID. The 1-D check stays
    next to the only code that can name `Connector`.
- `Page.create_shape` asks its document for the donor. `Page.connect` asks
  its document for the connector and hands it to the engine: the engine
  checks the ends before anything is written, as it does today, so
  `connectors._create_connector` splits into `_plan_connector(page, source,
  target, options)`, which checks and returns the two ends, and
  `_glue_connector(connector, begin, end, options)`, which writes them. The
  two function-local imports go, and the engine never names `Connector`.
- `copy_kind`, `copy_connector`, `media_style` and `_donor` stop being public
  `media` functions. They were added after 0.8.0, so no guide entries are
  needed. The tests that reach into `media` move to the new names.

### Every upward edge is a `Protocol` (#114)

The lower module declares what it needs, and the upper class satisfies it
structurally. pyrefly strict checks that wherever an upper object passes
itself down. Each `TYPE_CHECKING` import of an upper class goes.

**A wrapper asks its owner, and the owner asks the next.** Shapes, and the
connector engine, reach their document today through `shape.page.vis.<method>`,
which is a reach through two owners. The plan forbids that. It is also what
would force the seam in `shapes` to describe the document, whose methods take
`Page` arguments that `shapes` cannot name. So each call through `page.vis`
becomes a private method on `Page` that forwards to its own document:

| Today, in `shapes` or `connectors` | After |
|---|---|
| `page.vis._master_is_one_d(id, shape_id)` | `page._master_is_one_d(id, shape_id)` |
| `page.vis.get_master_page_by_id(id)` | `page._master_by_id(id)` |
| `page.vis._master_revision()` | `page._master_revision()` |
| `dst.vis._masters_for(ids, src.vis)` | `dst._masters_for(ids, src)` |
| `src.vis.copy_shape(xml, dst)` | `dst._copy_shape_xml(xml)` |
| `page.vis.renumber_shape_ids(xml, page)` | `page._renumber_shape_ids(xml)` |
| `dst.vis is not src.vis` | `not dst._same_document(src)` |
| `copy(page)` using its argument as a `Page` | `dst = self._page._peer(page)` |
| `media.copy_connector(page)` and the style check | `Page.connect`: `self._document._copy_connector(self)` |

A seam method whose argument is another object of the implementing class,
such as `Document._masters_for(ids, source)`, types the argument with the
seam. Where the implementation needs more than the seam holds (`source`'s
master catalog), it narrows with `isinstance(source, Document)`, and raises
`TypeError` otherwise. Every object that reaches it is a `Document`, so the
narrowing never fails.

The one public argument of that kind is `Shape.copy(page)`. It is typed
`PageView | None`, the type a caller holds. `shapes` cannot name `Page`, so
the shape asks its own page to narrow the destination:
`Page._peer(other: PageView) -> Page` returns `other` when it is a `Page`
and raises `TypeError` otherwise. A hand-written object that merely
satisfies `PageView` was never a valid destination, and now it fails with a
message rather than an `AttributeError` further in.

**Private seams**, where only the library reads through the reference:

- `swimlanes._DiagramPage` extends `shapes.PageView`, because a new lane is
  copied onto the page (`Shape.copy` takes a `PageView`), and adds
  `_attached()`.
- `connectors._ConnectorPage`: `name`, `shapes`, `_connects`, `_add_connect`
  and `_remove_connect_records`. `connectors._EndShape` and
  `connectors._ConnectorShape` cover the shape members in the table above.
  They read the page through `_page`.
- `pages._DocumentSeam(DocumentView)`: what `Page` reads off its document
  (`pages_xml`, `masters_xml`, `_package`, `_set_part_xml`,
  `_rename_page_in_app_xml`), plus the forwarded operations in the table:
  `get_master_page_by_id`, `copy_shape`, `renumber_shape_ids`,
  `_master_is_one_d`, `_master_revision`, `_masters_for`, `_kind_source`
  and `_copy_connector`. `pages.py` can name `Page`, so these signatures stay
  as they are.

**Public views**, where a caller reaches the object through a public
back-reference. The maintainer ruled on 2026-09-24: typed code keeps the
public API through these references, so the lower module declares a public
`Protocol` listing it.

- **`shapes.PageView`** is the type of `shape.page`, `shape.master_page` and
  the page half of `shape.parent`. Members: `name`, `background`,
  `index_num`, `xml`, `width`, `height`, `is_master_page`, `children`,
  `shapes`, `connectors`, `connect(...)`, `create_shape(...)`,
  `apply_text_context(...)` and `find_replace(...)`.
  - It leaves out `swimlanes`, `require_swimlanes` and `vis`: their types are
    declared above `shapes`, so the view cannot name them. It also leaves out
    the page's part-level attributes (`filename`, `page_id`, `rel_id`,
    `master_base_id`, `master_unique_id`, `rels_xml_filename` and
    `rels_xml`), the package internals "Out of scope" leaves to Phase 7. A
    caller uses the `Page` it holds for all of those. The guide says so.
- **`shapes._PageSeam(PageView)`** adds the private members `Shape` itself
  uses: `page_id`, `filename`, `rels_xml`, `_children`, `_attached`,
  `_delete`, `_connects`, `_ensure_page_master_rel`, `_carry_relationships`,
  `_peer`, and the forwarded operations in the table. It has no `vis`. The
  exact list is whatever pyrefly strict needs to type-check `shapes.py`,
  and no more. It also extends
  `connectors._ConnectorPage`, because the page a shape holds is the one
  the connector engine reaches.
- **`pages.DocumentView`** is the type of `page.vis`. Members: `pages`,
  `save(...)` and `render(...)`. `pages._DocumentSeam(DocumentView, ...)`
  adds the private ones.
- `Shape.page`, `Shape.parent` and `Page.vis` become read-only properties
  typed by the public view. The seam-typed reference is stored privately, as
  `Shape._page` and `Page._document`, and the library's own reads use it.
  Each property returns the same object as before, so behaviour and identity
  do not change.
- `Shape.__init__`, `Shape.copy` and `Page.__init__` take the seam or view
  type. `Shape.master_page` returns `PageView | None`.

With these in place, `UNRESOLVED` is empty and the ratchet's list is deleted.

### The import-graph test

`tests/test_import_graph.py` reads every `import` in `src/vsdxkit/*.py` with
`ast`: module-level, under `TYPE_CHECKING`, and inside functions. It fails:

- on any cycle among the resulting edges;
- on `from vsdxkit import <module>`, or `import vsdxkit` followed by an
  attribute that names a module. Importing a root constant by name is
  allowed.
- on a `TYPE_CHECKING` block that imports from `vsdxkit`.

It lands first with an `ALLOWED` set of the edges that break those rules
today, each with the step that removes it. It fails both ways, like the
annotation ratchet: a new violation fails, and so does a listed edge that has
gone. Each later step shrinks the set, and the last step deletes it.

## Delivery

It is one stack of three PRs, each passing every gate on its own.

1. **6a, #113: `render_document`.** The mixin goes. The guide gets its
   entries and `templating.rst` names `render_document`.
2. **6b, the graph test and the donors.** The test lands with `ALLOWED`. The
   media cycle, the root-sibling imports and `import vsdxkit` go.
3. **6c, the seams.** The page-level forwards, then the Protocols in
   `swimlanes`, `connectors`, `shapes` and `pages`, the public views and the
   properties. `UNRESOLVED` and `ALLOWED` both empty, and the lists are
   deleted. This closes #114 and #28. The seams go in one PR because they
   interlock: the connector engine reads `shape._page`, which only exists
   once `shapes` has its seam.

The guide, `classes.rst` and the mypy fixture are updated inside each PR, so
no separate docs PR is needed.

## Behaviour that must not change

- Every saved byte. The save-equivalence sweep against main reports 0
  differences on every PR.
- The Jinja fixtures, the sandbox tests, the README workflow and the recorded
  Visio observations.
- Wrapper identity: `shape.page`, `shape.parent` and `page.vis` return the
  same objects they return today. They become properties over the same
  stored reference.
- One import per process of each donor.

## Testing

- **Existing contract.** `test_jinja*.py`, `test_templating_sandbox.py`,
  `test_media*.py`, `test_create_shape.py` and the connector suites pass
  unchanged, apart from the private names they reach.
- **New tests.**
  - `Document.__bases__ == (object,)`, replacing the assertion that the base
    is the mixin.
  - `render_document` renders a document it is handed, with the same result
    as `Document.render`.
  - The import-graph test, with its own unit tests: a synthetic cycle, a
    `TYPE_CHECKING` upward import and a sibling reached through the root
    each fail.
  - The mypy consumer fixture does `shape.page.connect(...)`,
    `shape.page.shapes` and `page.vis.save()`. That proves the public views
    carry the API through a back-reference.
  - `shape.copy(page=<not a Page>)` raises `TypeError`, naming what it got.
  - Protocol conformance is checked by pyrefly strict and the mypy fixture,
    not by `runtime_checkable`.
- **Unchanged gates.** Python 3.10 and 3.14, ruff, format, pyrefly, the
  annotations check, the guide check, `sphinx -W`, the wheel smoke test and
  the sweep.

## Out of scope

- Other reach-throughs, outside `shapes` and `connectors`. Phase 6 removes
  the ones that cross an upward seam and leaves the rest to Phase 7.
- `Document`'s package internals that are still public, such as the ID
  helpers and `copy_shape`, and the page's part-level attributes
  (`filename`, `page_id`, `rel_id`, `master_base_id`, `master_unique_id`,
  `rels_xml` and `rels_xml_filename`). Phase 7 (#116).
- Renaming `page.vis`. The property keeps its name.
